# VibeKnowledge

这是独立技能包：只复制本文件夹即可使用，不需要原仓库、原视频、本机字体、旧虚拟环境或其他技能。显示名称和文件夹保持 `VibeKnowledge`，标准调用标识为 `$vibe-knowledge`。目标是让普通观众通过动画理解知识；沿用 HyperFrames + 确定性 Canvas/SVG + GSAP，不把不同主题套成同一套粒子模板。

首次使用阅读 [安装与独立使用](references/installation.md)。系统只需Python 3.10+、Node.js 22+（含npm）；首次安装运行依赖需要网络，音乐和完整中文字体已经随包提供。环境依赖不等于依赖原工作区。

## 必须执行的三阶段

用户明确要求两次审核，这是实际制作边界。收到一个新主题时只完成阶段一。用户没有回复、只问进度或只要求修改，均不等于通过；“继续”只有在上下文明确指向批准当前交付物时才算通过。

1. **脚本审核**：核实概念和案例，分析固定音乐，提交60–90秒完整叙事脚本及前30秒详细分镜。按 [脚本规范](references/script.md) 编写，文件放在新视频的 `docs/script.md`，事实来源放 `docs/sources.md`。在聊天里展示文案和重要分镜，再等待用户通过。此阶段不渲染视频。
2. **30秒样片审核**：仅在用户批准当前脚本后实现并渲染30秒MP4。先读 [视觉与动画规范](references/visual.md) 和 [制作流程](references/production.md)。展示实际视频及有证据的Review，通过和失败数量分开报告。收到修改意见就修样片，不能自行扩展全片。等待用户明确批准最终样片。
3. **完整版**：仅在用户批准当前样片后扩展到已批准的完整时长。保留样片已接受的画面、人物/符号含义、字形、音乐起点和技术栈。复用前30秒，只移除样片临时收尾，完成案例、现实映射与首尾呼应。交付MP4、SRT、源项目和最终Review。

将真实用户的批准原话和版本摘要记录在 `workflow.json`。用 `scripts/workflow.py` 记录和检查；它能发现批准后脚本/视频/Review被修改，不能替代真实用户授权。**不得为了让命令通过而编造批准原话或提前执行approve命令。** 重大脚本调整重新审核；新样片替换了已批准视频也要重新审核。

用户显式修改上述流程时，以用户当次指示为准，并记录修改；不能从“做得快一点”推断跳过审核。

## 固定内容与制作标准

- 每个视频都使用实际随包文件 [千年之后（氛围版）](assets/audio/千年之后_氛围版.ogg)，不得自动换歌、生成替代曲或依赖 Downloads 路径。元数据/校验值见 [音乐清单](assets/audio/manifest.json)，命令和卡点见 [固定配乐](references/music.md)。
- 16:9，1920×1080，30fps，MP4/H.264 + AAC双声道，无新增旁白。样片30秒；完整片通常60–90秒。
- 深色背景，金/白主色、少量红色；第一帧进入主题，前3秒明确冲突，前8秒建立问题。约17秒概念揭晓按实际音频卡点，不能牺牲阅读与推理时间。
- 中文短句，通常每行不超过18字；每字分别从下方遮罩上滑，不能只让整行淡入。保留整句可读时间。
- 重要动画必须表达具体机制：对象是什么、为何移动、观察到什么、遗漏什么。点要有连续运动与身份，不用随机装饰代替推理。框、连线必须有可理解的含义，必要时加贴近对象的短标签。
- 不把“渲染成功”“自动检查无错误”当作“观众理解了”。Review区分制作检查、警告和待观众验证项，不虚报零问题。
- 所有新项目文件在用户工作区下分类保存，例如 `videos/<主题>/`。不得覆盖其他主题、旧版成片或原BGM。

## 资源与执行入口

- 用 `python3 <skill>/scripts/workflow.py init <任意目标目录> --topic '主题'` 建立完整的独立项目骨架、字体和音乐副本。目标目录必须不存在；默认放在用户当前工作区下。
- 按当前阶段阅读对应参考，不要一次加载所有例子。
- `scripts/engine.py` 提供setup、doctor、build、check、snapshot、preview、render和verify；所有工具和项目路径动态解析，具体命令见 [制作流程](references/production.md)。不调用任何外部工作区的脚本。
- `assets/starter/` 是完整可构建的工程骨架，含锁定依赖、构建器、逐字字幕、连续运动库、场景扩展口与SRT/CSV输出。`assets/fonts/` 提供完整Noto Sans SC及许可证；`assets/audio/` 提供固定OGG及卡点数据。
- 每期都须按批准脚本编写 `config.json`、`captions.json` 和 `scenes.js`，完成后设置 `config.ready=true`。空骨架会拒绝构建，不能用测试动画冒充知识视频。
- [幸存者偏差脚本实例](references/survivorship-example.md) 仅供叙事参考；新主题不自动使用飞机、Wald或成功/失败配色含义。
- 脚本阶段的回复以脚本为主；样片/完整版阶段的回复以可播放视频和Review为主。每次请求审核时指出这是用户指定的阶段要求，并链接当前待审文件。
