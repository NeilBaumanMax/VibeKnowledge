# 阶段一：可审核的完整脚本

收到主题就开始资料核查和脚本，不重新询问已确定的比例、音乐、画风和流程。只有主题含义影响核心内容时才澄清；面向普通大众，默认完整时长78秒，可按叙事调整到60–90秒。

先提炼一句准确的核心命题，再选择一条观众熟悉的误区或问题。结构可用“冲突 → 直觉 → 反例/遗漏 → 概念 → 可观察的推理实验 → 现实应用 → 呼应开头”；根据知识机制调整，不能每个题目都硬塞二战飞机或成功者。

`docs/script.md` 按以下顺序组织，提交前写完实质内容：

1. 主题概括：核心命题、目标受众、必要边界。
2. 结构大纲：完整片时长和段落，明确样片30秒结束在哪里、完整版如何接续。
3. 逐秒分镜表：时间段、字幕、视觉对象、动作及因果含义、转场、音乐节点、观察/阅读停留。
4. 字幕时间轴：每句出现/消失时刻、逐字入场完成时间、重点词。多行先后出现分别记时。
5. 视觉风格：保留系列风格；定义本期每一种颜色、点、框、线和对象的含义，以及后续如何保持一致。
6. 音乐卡点：使用随包OGG及已测起音；约17秒揭晓，说明收暗、动作启动和文字落位。不要把所有事件机械地贴每一拍。
7. 动画实现思路：场景模块、数据结构、连续镜头、对象身份、知识推理过程。
8. 项目实现计划：将用哪些模块；此时只写计划，不提前渲染或伪称已经实现。
9. 自检计划：事实、阅读、遮挡、运动、音乐、输出规格、第一次观看理解问题。

知识核查：精确定义、常见误解、案例依据、教学简化边界记录在 `docs/sources.md`，优先原始文献/权威来源，区分事实和示意。原先飞机图的弹孔是教学示意，不可复制成历史统计数据。没有来源的数字不要包装成统计结论。

审核交付：在聊天里展示核心命题、字幕脚本和关键推理镜头，并链接完整方案；明确“脚本通过后制作30秒样片”。不能只给一份链接就让用户盲批。

例子阅读方式：`survivorship-example.md` 保留先前作品的时间轴和局部实现名，理解其因果设计即可，不执行其中旧路径或把旧事实当新主题内容。
